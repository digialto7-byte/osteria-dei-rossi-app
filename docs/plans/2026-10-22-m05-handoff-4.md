### Decisions and deviations, step 13
1. **`location_required` is answered in the UI.** The preview is called without a location, so with several locations the server always lists `location_required` and `canApprove` is false. The panel shows the `Select` and drops that blocker once a location is chosen (`visibleBlockers`); the server re-checks the chosen location when approving. With one location the body is `{}`. **Not covered end to end by Playwright** (the e2e seed has one location); it is covered by unit tests and the integration suite's single-location path. A multi-location e2e or int case would be a cheap follow-up.
2. **"Rifiuta" is `secondary`** (ui-foundation §8 says so; the plan's text said "quiet"). "Annulla" is quiet.
3. **Duplicate invoices get a reject-only panel** (no "Approva"), because the API allows `duplicate → rejected` and otherwise the owner could not dismiss one from the screen. Not in the plan's §3.8; one extra branch, unit-tested.
4. **Confirm step falls back to the blocker list** if an edit made while it is open brings a blocker back.
5. The component tests use static markup (no jsdom/testing-library in the repo, no new dependency), so the two-tap state machine and the error-persistence are proven only by Playwright (step 14).
6. English second-locale strings were written by me (not reviewed by a native speaker).
7. No `approval.final` key: the "cannot be undone" statement on an approved invoice is the `SuccessNote` text `approval.done`.
