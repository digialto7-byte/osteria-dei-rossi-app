## Decisions made

1. **Report response shape** is `{period: {from, to}, report}`, where `report` is the RPC jsonb untouched. The plan said only "200 report".
2. **Default report period** is 30 calendar days, today included: `to` = today in Europe/Rome, `from` = `to` minus 29. A missing bound is derived from the other one (`from` alone ends today). A `from` after the end is 400.
3. **Range limit** is checked in the API (366 days inclusive, 400 `invalid_request`) and again in the database (`range_too_long`, mapped to the same 400).
4. **The split sum check reads the parent** (`qty`, `line_amount`) through RLS before the RPC, in integer ten-thousandths, so the 422 can carry `qtyDiff` and `amountDiff` (children minus parent). Same for a credit with no `qty` in the body: the stored qty is read first. The database repeats both rules.
5. **`isStock: false` needs `costCentreId` in the same body** (422 before any call), even if the line already has a centre. The screen always sends both.
6. **`isStock: true` with a non-null `costCentreId`** is a 400 from the schema (the procedure would refuse it as `invalid_request`).
7. **Clearing values**: `null` is accepted for `unitPrice`, `vatRate`, `supplierCode`, `unit`, `lotCode`, `expiry`, `ingredientId` (unmap) and `costCentreId`; `qty`, `lineAmount` and `creditQty` cannot be null (the procedure refuses it).
8. **`PATCH /api/invoices/:id`** answers `{review}` (not `{invoice}`), so the screen re-renders from one payload.
9. **Cost-centre routes are owner/admin only** for GET too (chef 403), matching the table's RLS. They support `?active=true|false|all` like the other master lists.
10. **Header confidence** names in `lowConfidenceHeaderFields` use the `header_corrected_fields` vocabulary (`invoice_number` is reported as `number_raw`), plus `supplier_name` and `payment_terms`, which have no correction field. A field leaves the list once it is in `headerCorrectedFields`.
11. **A "mapped" line for the summary** counts leaves only (original lines that are not split, plus active parts). `summary.lines`, `unmapped`, `toCheck` and `corrected` follow that, and `gate.linesTotal` sums the same lines.

## Open questions

- Is the default report period "30 days including today" right, or should it be 30 days before today (decision 2)? One line in `parseExtractionQualityQuery`.
- Should chef be allowed to read `/api/cost-centres` (decision 9)? The table's RLS says no, and V3 would change both together.
- `loadInvoiceReview` reads lines with a limit of 1000. The extraction caps an invoice at 200 original lines and a split adds at most 10 parts each, so the worst case is above 1000. Real invoices will not reach it, but a truncated list would silently hide lines. Raise the limit or fail loudly if you disagree.
- Carried over from batch 1 and still open: whether changing a mapped line's `unit` should update `supplier_item.invoice_unit`; whether `p_status = 'all'` should include `approved`; whether the picker should hide inactive ingredients (the API does not filter them out of the review payload); CI `supabase test db` on the real stack has not run for batch 1.
