## 3. Design

### 3.1 Decisions

1. **CSP (ADR-028): a per-request nonce set in the proxy; every app page renders per request.**
   - **Nonce:** `createNonce()` (`src/lib/security/nonce.ts`) returns 16 bytes from `crypto.getRandomValues`, base64 encoded: 24 characters ending in `==`, 128 bits.
     - The Next.js guide's `btoa(crypto.randomUUID())` gives only 122 random bits, so it is not used.
   - **Builder:** `buildCsp({ supabaseOrigin, deployment, dev, nonce })` (`src/lib/security/csp.ts`). For a page (`nonce` set), it returns:

     ```
     default-src 'self'; script-src 'self' 'nonce-<n>' 'strict-dynamic'; style-src 'self' 'unsafe-inline';
     img-src 'self' <supabase>; frame-src <supabase>; font-src 'self'; connect-src 'self';
     worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self';
     frame-ancestors 'none'[; upgrade-insecure-requests]
     ```

     - With `nonce: null` (the **static policy** for non-pages), `script-src` is exactly `'self'`, and everything else is the same.
     - `'unsafe-eval'` is appended to `script-src` only when `dev`.
     - `upgrade-insecure-requests` is added only for `production` and `preview`.
     - `<supabase>` is the origin of the Supabase URL.
     - The builder throws `csp_invalid_nonce` unless the nonce matches `^[A-Za-z0-9+/]{22}==$`, so nothing can be injected into the header. It throws `csp_invalid_origin` on a non-http(s) origin.
     - **`'unsafe-inline'` never appears in `script-src`.**
   - **`'strict-dynamic'`: included.**
     - It is not strictly needed for Next 16's chunk loading, because the chunks are same-origin and `'self'` would admit them.
     - It is included for two reasons:
       - (a) it is the Next.js guide's documented form;
       - (b) CSP3 browsers then ignore `'self'`, so only nonced scripts and the scripts they load can run. A parser-inserted `<script src="/…">` from our own origin is refused.
     - `'self'` stays as the fallback for browsers without CSP3.
     - Sources: the Next.js CSP guide and MDN `script-src` (§9). Step 4's violation collector proves it on Chromium and WebKit, and steps 4a and 17 on Chromium (T1).
   - **`style-src 'self' 'unsafe-inline'` (Q234).**
     - A nonce in `style-src` would make browsers ignore `'unsafe-inline'`, and nonces never cover `style=""` attributes. The server-rendered bar width in `plate-breakdown.tsx` would then be blocked.
     - Style injection cannot run script, and exfiltration through CSS `url()` is limited by `img-src` and `font-src`.
     - Q234 asks whether to tighten it anyway.
   - **`cspForRequest(nonce, source = process.env)`** builds the page policy at runtime:
     - the Supabase origin from `readPublicEnv(source).supabaseUrl`;
     - the deployment from `source.VERCEL_ENV`, validated against `production | preview | development`, defaulting to `development`;
     - `dev` = `source.NODE_ENV === "development"`.

     The CI server is `next start`, so `dev` is false there.
   - **Who sends what:**

     | Response | Matched by the proxy? | CSP sent by | Policy |
     |---|---|---|---|
     | Every page, RSC navigation and prefetch, the 404 page, and the proxy's own redirects | yes | the proxy (step 2a) | page policy with this request's nonce |
     | `/api/*` | yes (session refresh) | `next.config.ts` rule `/api/:path*` | static (`script-src 'self'`) |
     | `/sw.js`, `/manifest.webmanifest` | no | `next.config.ts` rules | static |
     | `/_next/static/*`, `/_next/image`, image files | no | none | not documents (no SVG or HTML is served from `public/`) |

     - `/:path*` keeps `nosniff`, `Referrer-Policy`, `X-Frame-Options: DENY` and HSTS (production), and **no CSP**. Every response therefore carries **at most one** policy. Steps 3 and 4 check that.
   - **Proxy (step 2a):**
     - For a non-`/api/` path, `proxy()` makes a nonce and builds `cspForRequest(nonce)`.
     - It copies the incoming request headers and **overwrites** `x-nonce` and `content-security-policy`, so a forged incoming value is never forwarded.
     - It calls `updateSession(request, requestHeaders)`. Every `NextResponse.next(...)` inside it is built with `{ request: { headers: requestHeaders } }`, including the one rebuilt in `setAll` after a cookie refresh.
     - It then sets the same policy string on the response, redirects included.
     - For `/api/*` it deletes any incoming `x-nonce` and calls `updateSession(request, requestHeaders)` without a policy.
     - **Next reads the nonce from the forwarded `content-security-policy` request header** (Next.js guide). `x-nonce` is for our own code (the root layout).
   - **Dynamic layout (step 2b):** `RootLayout` becomes `async` and calls `requireNonce(await headers())`.
     - `headers()` makes the whole tree render per request.
     - `requireNonce` throws `csp_nonce_missing` when the proxy did not run, so the page fails closed.
     - The nonce value is not put in our markup: Next stamps it on its scripts.
     - No file in `src/app` may set `dynamic`, `revalidate` or `dynamicParams` (guard).
   - **What stays pre-rendered (step 4, T2):** the sorted keys of `routes` in `.next/prerender-manifest.json` equal exactly **`["/manifest.webmanifest"]`**. Any other entry is a stop: report to the architect, never a silent list edit, because a pre-rendered HTML page would carry a nonce-less script under a nonce header.
   - **Matcher: unchanged** (T17).
     - The Next.js guide's matcher skips `api` and prefetches. Ours must not: the proxy refreshes sessions on `/api/*` and redirects signed-out navigations, prefetches included.
     - Static assets stay excluded, as M20 requires for `sw.js` and the manifest.
     - Prefetches and RSC requests therefore get a nonce and a render. Step 21 counts them.
2. **Header check (AT2).**
   - `checkHeaders(replies, expect)` (`src/lib/security/header-check.ts`) checks `GET /login` (twice), `GET /api/health` and `GET /sw.js`. All must have:
     - `nosniff`;
     - `Referrer-Policy: strict-origin-when-cross-origin`;
     - `X-Frame-Options: DENY`;
     - **exactly one** CSP (none is `csp_missing`; a value containing `", "` means two policies were merged: `multiple_csp`);
     - in the CSP: `default-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'` and `connect-src 'self'`;
     - in `script-src`: **no `'unsafe-inline'`**, **no `'unsafe-eval'`** and **no origin**.
   - **`/login`:** `script-src` = `'self' 'nonce-<n>' 'strict-dynamic'`. `<n>` decodes to at least 16 bytes (`nonce_short`). The two fetches carry different nonces (`nonce_reused`).
   - **`/api/health` and `/sw.js`:** `script-src` = exactly `'self'`.
   - `style-src 'unsafe-inline'` is accepted and reported as `note: style-src unsafe-inline (ADR-028)`.
   - HSTS (`max-age` ≥ 31 536 000 and `includeSubDomains`) is required only for `--expect production`.
   - `scripts/check-headers.ts`:
     - `https` only, except localhost;
     - `redirect: "manual"`;
     - sends `x-vercel-protection-bypass` from `VERCEL_AUTOMATION_BYPASS_SECRET` when set (T8);
     - prints one JSON line with header names and findings only (no nonce, no header value);

13. **Service worker and offline under the nonce policy (step 4a).**
    - **Why it is self-consistent:**
      - A shell page in the cache is the full `Response` of one render: its HTML, whose inline scripts carry nonce N, and its headers, whose CSP carries the same N.
      - Served offline, or after the 3-second timeout, the browser applies the cached header to the cached HTML, so N matches N.
      - Chunks come from the `static-<version>` cache. They are loaded by those nonced scripts (`'strict-dynamic'`) or by `<script src nonce=N>` tags.
    - **Rules the worker already keeps, and which become load-bearing:**
      - it never rewrites a cached page's body or headers;
      - it replaces body and headers together (`shell.put(key, response.clone())`);
      - the shell cache is per deploy version, so a page's chunk names match its cache.
    - **Change:** the synthetic "Sei offline" page gets a fixed header, `content-security-policy: default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. It has no script and keeps its inline `style`. So every document of our origin carries a policy.
    - **Nonce reuse:** a cached page replays its own nonce on that device until it is refreshed online. That is accepted, because the bytes are our server's own render with nothing injected afterwards, and every network response gets a fresh nonce (ADR-028, consequences).
    - **Proof:**
      - unit: the harness's `FakeCache` stores headers, and new `sw.test.ts` cases show the cached header string is byte-identical and is replaced only together with the body;
      - e2e: `e2e/pwa.spec.ts` (Chromium) reloads the comanda offline and checks the served document's nonce against every script and every cached shell entry, with violations `[]`.
      - WebKit's service worker under Playwright is not covered (T16). The nonce itself is checked on WebKit by step 4.

### 3.3 Sequence of calls

1. **Page request** (document, RSC navigation or prefetch):
   1. Vercel → `proxy()`;
   2. `createNonce()` → `cspForRequest(n)`;
   3. request headers `x-nonce: n` and `content-security-policy: <policy>` (incoming values overwritten);
   4. `updateSession(request, headers)`: session refresh, the 30-day end, sign-in redirects;
   5. the response (or redirect) gets the same `content-security-policy`;
   6. Next renders per request: the root layout calls `requireNonce(await headers())`, Next reads `n` from the request policy and stamps it on every script it emits;
   7. the browser runs only scripts with `n` and what they load.
2. **API request:** `proxy()` → `x-nonce` removed → `updateSession` → the route. The static CSP comes from `next.config.ts`.
3. **Offline shell:** SW `shellNavigation` → network fails or takes over 3 s → the cached `Response` (header nonce = script nonce) → the page runs. Any other page → "Sei offline" with its fixed no-script policy.
4. **Daily (02:15 UTC):**
   1. `backup` job (`production-backup`);
   2. guards;
   3. `npm ci`;
   4. dump → manifest → tar → gpg → SHA-256;
   5. Drive upload with MD5 check, retention 14;
   6. keep-alive ping;
   7. clean-up;
   8. on failure, an issue.
5. **Weekly (Monday 04:00 UTC):**
   1. `restore` job;
   2. Drive: newest copy, age ≤ 36 h, MD5;
   3. decrypt → empty stack → restore → checks (a)–(d);
   4. summary (names and counts only);
   5. clean-up and `supabase stop --no-backup`;
   6. on failure, an issue.
6. **Release:**
   1. merge → CI → staging migrations;
   2. the founder runs `deploy-production` (approval);
   3. the founder promotes the Vercel deployment (T9);
   4. header check on production.

## 4. Alternatives considered

- **The static CSP with `'unsafe-inline'` (revision 2, built in `596b9d6`):**
  - it kept pre-rendering;
  - rejected by the founder (second round), because an HTML-injection bug would run script.
- **Hashes in a static CSP:**
  - impossible for Next.js's per-page flight scripts;
  - any hash also disables `'unsafe-inline'` (ADR-028).
- **Next.js experimental SRI:** it hashes JavaScript files, not inline flight scripts, and it is experimental.
- **Nonce without `'strict-dynamic'`:**
  - it would work, because the chunks are same-origin;
  - rejected because CSP3 browsers would still honour `'self'` for parser-inserted scripts, and it is not the guide's tested form (§3.1.1).
- **Nonce in `style-src`:** it blocks the existing `style=""` attribute. Not the default; Q234 → V2.
- **The guide's matcher (no `/api`, no prefetches):** rejected. It drops session refresh on `/api/*` and the sign-in redirect for prefetches.
- **`btoa(crypto.randomUUID())` as the nonce (the guide's example):** 122 random bits, under the 128 required.
- **`await connection()` in the root layout:**
  - equivalent for dynamic rendering;
  - `headers()` is chosen because the same call lets the layout fail closed when `x-nonce` is missing.
- **Setting the page CSP in `next.config.ts` and overriding it in the proxy:** rejected. It relies on header precedence between the two, which this session could not verify. One source per path is simpler to test (`multiple_csp`).
- **The SW rewriting cached pages to a fresh nonce:** rejected. The worker would edit HTML, which needs a parser, adds risk and gains nothing: a cached page is consistent as stored.
- **`require-trusted-types-for 'script'`:** not verified with Next.js 16 and React 19, and needs reporting to trial (ADR-028).
- **CI options A (timeout 40), C (two workers), D (own job):** the founder chose B. C is unsafe today: a shared sign-in budget (`supabase/config.toml` lines 212, 214) and specs that run cross-tenant jobs (`alert-rules`, `reports`, `dashboard`, `exports`, `push-forecast`, `demo-data`, `seed-order` helpers).
- **Shards sharing one build through an artifact:** rejected. The build inlines each runner's local Supabase settings, and the upload and download cost minutes.
- **pgTAP and integration in a separate job before the shards (`needs:`):** rejected. It costs one more `npm ci` + `supabase start` per run (more minutes) for the same order. `fail-fast` already stops shard 2 when shard 1's database tests fail.
- **A restore check inside the daily job:** rejected. It is weekly by the founder's answer, and a separate job that downloads from Drive also proves the real recovery path (download + MD5).
- **Supabase Pro daily backups:** not chosen (Q187, Free).
- **`googleapis`, `rclone`, `age`, plain `pg_dump`, GitHub artifacts, Workload Identity Federation:** rejected as in the first version (no new dependency; version match; no production data in artifacts).
- **A keep-alive through a scheduled call to the app:** rejected. `/api/health` does not touch Supabase. The backup job already connects every day, and it pings Auth directly.
- **`public.ledger_invariants_run()` for "clean":** rejected. It writes and includes environment-dependent job health (A2).
- **A new timing script for page loads:** rejected. The 4G workflow already times `/` end to end, and the build output and the Vercel Usage page cover the rest (§3.1.14).

## 6. Risks and mitigations

- **Security and privacy**
  - **Inline-script injection: closed by the browser** (nonce, no `'unsafe-inline'` in `script-src`, `'strict-dynamic'`), and still by React escaping and the raw-HTML guard (2).
    - Residual risks:
      - `style-src 'unsafe-inline'` (Q234);
      - a page or response the proxy does not cover. The layout fails closed (2b), the matcher test stays green (2a), and the header check catches a missing (`csp_missing`) or doubled (`multiple_csp`) policy (3).
    - Both are recorded in the walk (20).
  - **The nonce is unguessable and single-use per response:** 128 bits from `crypto.getRandomValues` (2). A forged incoming `x-nonce` or request CSP is overwritten (2a). The nonce is never printed by the header check (3).
  - **New risk: the offline shell and its nonce (4a).**
    - A cached shell replays the nonce of its own render on that device. That is self-consistent and needs no rewrite.
    - Exposure: the cached bytes are our server's render, with no injection afterwards. The nonce is visible in that page anyway.
    - What would break it:
      - a worker change that edits cached HTML or headers separately;
      - a pre-rendered page sneaking back in (a nonce-less script under a nonce header).
    - Guarded by the byte-identical header test and the paired-replace test (4a), the exact pre-render list (4), and the offline e2e with violations `[]` (4a).
    - The offline page itself carries a no-script policy (4a).
    - **WebKit's service worker is not exercised by Playwright here (T16).** The nonce is checked on WebKit online (4). An offline check on a real iPhone against staging goes on the go-live checklist (20).
  - *The CSP breaking a flow:*
    - every spec runs under it;
    - violation collectors run in 4, 4a and 17;
    - the invoice iframe is covered (4);
    - the founder checks preview first (§8).
  - *Backups:*
    - AES-256 with a passphrase only the founder holds (Q181);
    - clear text only in `$RUNNER_TEMP`, removed in `always()`;
    - no GitHub artifacts;
    - the Drive key scoped to `drive.file` and one folder;
