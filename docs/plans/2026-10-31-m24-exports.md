## 1. Goal and scope

- **Goal:** every report the owner reads in the app can leave it as a CSV that matches the screen exactly. Each month, a printable pack (KPIs, purchases, waste, variance) can be saved as a PDF for the accountant, from the phone or the laptop.
- **In scope**
  - **`GET /api/exports/:report.csv`** for the 11 report tables of §3.1.2. Owner and admin only; chef and waiter get 403 before any RPC (AT4).
  - **`src/lib/csv/write.ts`:** a small RFC 4180 writer with typed cells, formula escaping (AT2) and the Q170 format.
  - **`src/server/exports/`:** the registry that binds each slug to the JSON route's own query schema and service (ADR-027). No SQL.
  - **`GET /api/exports/monthly-pack?month=YYYY-MM`:** the pack as JSON, composed from the KPI, waste and AVT services.
  - **`/report/mese`:** the print view. A global print stylesheet sets A4, hides navigation and prints in the light palette (AT3).
  - **"Scarica CSV" links** on the screens that show each table, plus a "Pacchetto mensile" link on `/report`. Shown to owner and admin only.
  - **M23 follow-up:** P0001 `menu_price_missing` from `push_menu_item` when a temporary price is given and no menu price is in force. It gets its own 422 code and Italian and English messages, shown in the push sheet (steps 1–2).
  - **Tests:** pgTAP `264`, Vitest (unit, route, parity, guards), one integration suite, Playwright.
- **Out of scope**
  - the accountant export with VAT breakdown and the accountant role (M36);
  - server-side PDF, e-mailed or scheduled packs (project §4; revisit with M36);
  - CSV of non-report lists: payables, supplier statements, invoices, master data. Also the daily app-vs-register check, the extraction-quality metric and the costing screens (Q169 → V3 for the first three);
  - a per-supplier purchases breakdown (Q173 → V4);
  - any change to a report's SQL, figures or roles in JSON;
  - any change to push behaviour beyond the error code (Q177 → V6).

## 3. Design

### 3.1 Decisions

1. **Exports are a rendering of the JSON services (ADR-027).**
   - Each export is an `ExportTable` in `src/server/exports/registry.ts` with:
     - `slug`;
     - `query`: **the same schema object** the JSON route passes to `parseQuery`, or the same parse function (`parseWasteCostsQuery`, `parseVarianceQuery`, `parseReconciliationQuery`);
     - `load(supabase, session, query)`: **the same service call** as the JSON route;
     - `rows(output)`, `columns(role)`, and `range(output)` (the file-name part).
   - No file under `src/server/exports/` calls `.rpc(` (guard, step 4). AT1 therefore holds by construction, and it is tested anyway (steps 7, 12).
   - The JSON routes are **not** changed.
2. **The 11 report tables (default of Q169).** Columns are Italian snake_case, as in the M1 import template.

   | Slug | Same query as | Rows | Columns (in order) |
   |---|---|---|---|
   | `kpis` | `/api/reports/kpis` (`periodQuery`) | 54 fixed rows (`KPI_CSV_ROWS`): the 23 scalar figures, then `coversByHour` 00–23, then `coversByWeekday` 1–7 (Monday = 1) | `chiave;voce;valore;valore_precedente;differenza;differenza_pct`. The two delta columns are filled for the 12 `DELTA_KEYS` rows only |
   | `items` | `/api/reports/items` | `rows` | `menu_item_id;piatto;portata;piatti;mix_pct;ricavi_netti_eur;piatti_con_costo;ricavi_netti_con_costo_eur;food_cost_eur;food_cost_pct;margine_cibo_per_piatto_eur;stato`, plus, **owner only**: `costo_fisso_per_piatto_eur;margine_lordo_per_piatto_eur;contributo_eur;motivo_costo_fisso` |
   | `avt` | `/api/reports/avt` | `rows` | `ingredient_id;ingrediente;unita;consumo_reale;consumo_teorico;scarti;scostamento;costo_unitario_eur;scostamento_eur` |
   | `unmapped-items` | `/api/reports/unmapped-items` | `rows` | `menu_item_id;piatto;piatti;ricavi_lordi_eur;ultima_vendita` |
   | `discards-vs-push` | `/api/reports/discards-vs-push` | `rows` | `recipe_key;preparazione;durata_ore;lotti_scartati;lotti_in_evidenza;porzioni_scartate;porzioni_in_evidenza;valore_eur;senza_costo` |

   - **No column carries a staff name or any other personal data** (asserted in step 7).
   - Ids are kept, so a spreadsheet can join files.
3. **CSV format (default of Q170, in `src/lib/csv/write.ts`, `CSV_FORMAT`).**
   - Separator `;`. Decimal comma. No thousands separator. UTF-8 with BOM (`EF BB BF`). CRLF, including after the last row. A header row.
   - A field is quoted when it contains `;`, `"`, CR or LF, or is formula-escaped. `"` is doubled.
   - **Cells are typed** (`text`, `number`, `date`, `instant`, `bool`):
     - `number`: the JSON value at up to 4 decimals with trailing zeros dropped (`38.0002` → `38,0002`, `-3.5` → `-3,5`, `22` → `22`, `-0` → `0`). Output always matches `^-?\d+(,\d{1,4})?$`. A non-finite value throws;
     - `date`: `2026-11-04` → `04/11/2026`;
     - `instant`: `2026-11-04T19:00:00Z` → `04/11/2026 20:00`, in Europe/Rome (DST-safe through `Intl`);
     - `bool`: `sì`/`no`;
     - **null: an empty cell, never `0`** (M8 rule: unknown is never zero).
   - **Precision (Q171 default):** the JSON precision is kept, so values and totals equal the screen's data.
4. **Formula injection (AT2, project §3.11.6).**
   - A `text` cell whose first character is `=`, `+`, `-`, `@`, tab (U+0009) or CR (U+000D) is written as `'` + text and quoted (`"'=1+1 (demo)"`).
   - Number, date, instant and bool cells come only from typed formatters, so they never need it. A negative number stays numeric.
   - Tab and CR go beyond the four characters the project plan names; they are a defensive addition.
5. **Routes.**
   - `src/app/api/exports/[file]/route.ts` serves `:report.csv`. `[file]` must match `^[a-z-]+\.csv$` and name a registry slug; otherwise 404. Because `withApi` checks the role before params, a chef asking for an unknown file gets 403, which reveals nothing.
   - `src/app/api/exports/monthly-pack/route.ts` is a static segment, which wins over `[file]` (T3).
   - The CSV reply:
     - `200 text/csv; charset=utf-8`;
     - `Content-Disposition: attachment; filename="report-<slug>-<range>.csv"` (ASCII only);
     - `Cache-Control: no-store` (from `withApi`) and `Server-Timing`.
   - **Errors stay JSON** (`{"error":{"code","message"}}`), with the JSON route's statuses (400, 401, 403, 404, 422, 500).
6. **Roles: owner and admin for every export and the pack** (project §3.3, AT4; Q176).
   - `withApi({ roles: ["owner","admin"] })` refuses the chef and the waiter **before any RPC**, even for the four tables the chef reads as JSON. Every RPC also checks the role in SQL (unchanged).
   - `items.csv` follows the caller's role: the admin's file has no fixed-cost columns (Q107).
7. **Monthly pack (`GET /api/exports/monthly-pack?month=YYYY-MM`, `src/server/exports/monthly-pack.ts`).** Every date comes from the KPI reply, which takes it from SQL business dates.
   1. `getKpiReport(supabase, { period: "month", date: month ? `${month}-01` : undefined })`. Without `month`, `kpi_report`'s own default anchor applies: yesterday's business date, so the month that contains it (Q174).
   2. With `from`/`to` = `kpis.current.from`/`.to`, in parallel:
      - `getWasteCosts(supabase, { from, to })`;
      - the AVT selection (8).
   3. Reply (strict `monthlyPackOutput`, reusing `kpiReportOutput`, `wasteCostsResponse`, `avtOutput`):

      ```
      { month: "2026-10", from, to, final, previousMonth, nextMonth,
        kpis: KpiReport, waste: WasteCosts,
        variance: { state: "ok", avt } | { state: "noCount" } | { state: "noOpening" } }
      ```

      - `previousMonth` = the month of `kpis.previous.from`;
      - `nextMonth` = the month of `to + 1 day` when `final`, else null. A final month ends before today's business date, so the next month's first day is never in the future.
   - **Purchases** are `kpis.current.purchasesEur` / `purchasesUnvaluedCount` against `previous` and `delta.purchasesEur` (Q173).
   - **Waste** is the whole `waste_costs` reply for the month. Its `valueEur` equals `kpis.current.waste.valueEur`, because the KPI embeds the same function (step 12 checks this).
8. **Which AVT goes in a month's pack (Q172, Q175).**
   - Call `getAvtReport(supabase, {})` (the latest count) and read `availableCounts`.
   - Pick the latest count whose `venueDate(closedAt)` falls in `[from, to]`:
     - if it is the one already answered, use it;
     - otherwise make one more call with `{ count: id }`;
     - if there is none, the state is `noCount` (no second call).
   - A 404 `not_found` (no monthly count at all) → `noCount`. A 422 `avt_no_opening_count` → `noOpening`. With the venue's single location (M22 A1), the latest count is then the only count. Any other error passes through.
   - This is selection, not arithmetic, and it runs in the server service. React receives the state.
9. **Print view `/report/mese?mese=YYYY-MM`** (`src/app/(owner)/report/mese/page.tsx`), inside the normal shell, so "Report" stays the current section.
   - The page reads `GET /api/exports/monthly-pack[?month=]` once and renders four `section`s with `h2` "Indicatori", "Acquisti", "Sprechi", "Scostamenti", under the `h1` "Pacchetto mensile · ottobre 2026".
   - The screen-only controls are wrapped in `data-print="hide"`:
     - the `BackLink` to `/report` (first link, house B5);
     - the "Stampa o salva PDF" button (`window.print()`);
     - the month links from `previousMonth`/`nextMonth`.
   - A "Provvisorio" badge shows when `final` is false.
   - **Print stylesheet (global, `src/app/globals.css`):**
     - `@media print { @page { size: A4; margin: 12mm } }`;
     - `nav`, `[data-slot="sync-status"]`, `[data-slot="nav-placeholder"]`, `[data-slot="sidebar-placeholder"]` and `[data-print="hide"]` → `display: none !important`;
     - the dark palette's media query becomes `screen and (prefers-color-scheme: dark)`, so paper always gets the light palette.
   - The demo-data banner stays on paper (Q178).

## 4. Alternatives considered

- **CSV generated in SQL (`*_csv` functions):** rejected (ADR-027). It is a second data path per report, and it adds public functions to every pinned list.
- **CSV built in the browser from the screen's JSON:** rejected. It puts formatting and escaping in React, against the invariant, and gives no single tested format.
- **A CSV library (papaparse, MIT):** rejected, as in M1 for the reader. A typed writer of a few dozen lines is fully tested here and adds no supply-chain surface.
- **Escaping every cell that starts with `-`, numbers included:** rejected. Negative amounts and quantities would become text and break sums in the accountant's spreadsheet. Typed cells escape text only.
- **Rounding amounts to cents in the CSV:** not the default (Q171 → V2). Totals in the file would stop adding up to the app's totals, and AT1 asks for equal values.
- **Server-side PDF (headless Chrome on Vercel or a PDF library):** rejected (project §4). It needs a new dependency, faces function size and time limits, and gains nothing the browser's "Save as PDF" lacks.
- **A print layout outside the shell (`/stampa/mese`):** rejected (ADR-027). It would be a second layout, and Report would not be highlighted. A global print block also fixes printing everywhere else.
- **Redefining the colour tokens inside `@media print`:** rejected. It duplicates every token that `src/lib/design/tokens.ts` mirrors. Limiting the dark palette to `screen` is one word.
- **A new SQL function for the pack:** rejected. The KPI, waste and AVT functions already answer for a month, and the pack must agree with the screens.
- **One combined "export everything" ZIP:** rejected. It needs a ZIP dependency, and the per-screen links match how the owner works.
- **Exports for the chef without €:** rejected by the milestone's AT4. A change is a re-plan (Q176).
- **Reusing `price_missing` for the follow-up:** rejected. That code means "this item cannot be sold" in order entry. The lead asked for a distinct code and messages.

## 6. Risks and mitigations

- **Security and privacy**
  - *Cost data reaching the chef or the waiter through a file.*
    - 403 at the route before any RPC (7, 8);
    - each RPC's own SQL role check (unchanged);
    - links hidden for them (11);
    - `items.csv` follows the caller's role schema, so the admin gets no fixed costs (4, 7).
  - *A cached CSV on a shared phone.* `Cache-Control: no-store`. The service worker caches only the four waiter reads, and `offline-cache-allowlist.test.ts` fails if an export imports the marker (also guarded in 4).
  - *Formula injection* (CSV opened in Excel or Sheets): typed cells and the text escape (3, 7); real data (12).
  - *IDOR / tenancy:* no id is taken from the client except the existing `count`/`session`/`location` filters, which the RPCs resolve within `app.tenant_id()`. A cross-tenant scan is in step 12.
  - *File-name injection:* the name is built from the slug (registry) and ISO dates only.
  - *CSRF:* GET only, no state change. A cross-site link can at most make the owner's own browser download their own data; `SameSite=Lax` and CORS same-origin prevent reading it.
  - *Personal data (GDPR):*
    - no in-scope CSV or pack section carries a staff name (7, 12);
    - the files leave the app and land on the owner's device, which is the client's (controller's) responsibility. This is noted for project Q13;
    - nothing is stored, so nothing new has a retention (project Q14 unchanged);
    - logs carry codes only (`reportError` by SQLSTATE).
  - *The replaced definer twin:* it keeps `security definer` and `search_path = ''`, is revoked from every API role and is still called only after `app.require_menu_writer()` (1).
- **Correctness**
  - *CSV and screen drifting apart:* the same parser and service objects (identity checks, 4–6), the no-`.rpc(` guard (4), parity unit and integration (7, 12).
  - *Precision:* numbers keep 4 decimals. If any reply carried more, the exact parse-back in 12 would fail (T2).
  - *Count closed after midnight:* assigned to the Rome calendar date of `closedAt` (Q175). This is tested with a 00:30 CET fixture (8), and the integration computes the expectation from the reply (12).
  - *A provisional month:* "Provvisorio" badge, no "next month" link (8, 10).
  - *Dark-mode printing:* the dark palette is `screen` only (9, 13).
  - *The push sheet still shows "Prezzo del menu" from `/api/menu/items` for a plate whose only price starts later:* unchanged M23 behaviour, outside the follow-up's brief. The refusal message (2) now says what is wrong.
- **Unverified (proved in the named step)**
  - **T1:** Chromium honours `@page { size: A4 }` inside `@media print` with `page.pdf({ preferCSSPageSize: true })`. Proved by the MediaBox assertion in 13. If Chromium writes the MediaBox numbers in another precision, step 13 widens the regex to the observed A4 values and records them in the spec. No PDF library is added.
  - **T2:** every number in the 11 replies has at most 4 decimals (money `numeric(12,4)`, percentages rounded to 2, hours to 1). Proved by the exact parse-back on real data in 12.
  - **T3:** in Next.js 16, the dynamic segment `[file]` receives `kpis.csv` (a dot inside the segment), and the static `monthly-pack` segment takes precedence over `[file]`. Unit tests call the handlers directly, so they cannot prove routing. Proved over HTTP in 13. If the dot is not routed, the path becomes `/api/exports/csv/[report]`, and the project plan §3.3 change is recorded.
  - **T4:** a menu item named "=1+1 (demo)" passes `POST /api/menu/items` (the TS schema accepts any non-blank text ≤ the max; the SQL `name_invalid` rule was not read). Proved in 12. If refused, step 12 uses the ingredient "-Burro (demo)" through the M1 API for AT2.
  - **T5:** `kpi_report('month', 'YYYY-MM-01')` answers `current.from` = the 1st and `to` = the last day of that calendar month (M22: "month → the previous calendar month" for the comparison). Proved by the deep-equal in 12 and by the dates the pack page shows.
- **Performance and cost:** no figure is promised. A CSV costs the same RPC as its JSON route, plus an in-memory string no larger than the JSON reply. The pack costs 3 RPCs, 4 at most. No new provider, job or paid service.
- **Dependencies:** none added (`no-new-deps.test.ts`, step 7).
