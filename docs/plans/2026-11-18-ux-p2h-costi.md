# P2h — Costì re-skin step 7: Gestione, Anagrafica, Registro (costi-design-system §11)

- **Date:** 2026-11-18 · **Branch:** `feat/ux-p2h-costi` · **Pattern:** P2d–P2g (ADR-045)
- **Scope:** UI only (`src/app/(owner)/**`, `src/components/**`, `tests/components/**`, `tests/lib/**`, `e2e/**`). No API, SQL, config.

## What the guard says
Raising `DONE` to 7 in `tests/components/costi-theme-order.test.ts` fails on:
1. **11 roots without `CostiTheme`:** `ricette`, `costi`, `anagrafiche`, `personale`, `registro`, `impostazioni`, `menu`, `dispositivi`,
   `doppia-verifica`, `password`, `sicurezza`. None has a `layout.tsx` yet.
2. **4 hand-written `<dl>`**: they are the last importers of `Detail` / `DETAIL_LIST_CLASS` (`src/app/(owner)/fatture/detail.tsx`):
   - `costi/fixed-cost-card.tsx`
   - `costi/ricette/[key]/page.tsx`
   - `anagrafiche/fornitori/[id]/estratto-conto/statement-view.tsx`
   - `ricette/[key]/recipe-facts.tsx`
3. **1 `font-display`**: `menu/menu-item-form.tsx`.

## Steps (one commit each, test first)
1. **Guard first.** Raise `DONE` to 7. It goes red on the 16 items above; that is the failing test for the whole step.
2. **Layouts.** Add a `layout.tsx` to each of the 11 roots: `<CostiTheme />` + children, the same as `report/layout.tsx`, with the same
   comment. The page stays a direct child of `main` (the `.reveal` stagger). Add every new layout to any list test that enumerates layouts:
   grep `tests/` for `layout.tsx`, e.g. `tests/lib/reports/no-money-math.test.ts`.
3. **FactList for the four `<dl>`.** Move each to `FactList` / `FactRow` (`src/components/fact-list.tsx`):
   - Keep every `data-testid` on the value, the labels, and the "value not found is left out" behaviour. `FactRow` must skip null and empty
     values the way `Detail` did; check how P2e/P2f migrated `fatture/[id]` and `magazzino`.
   - Keep `numeric` values as `num` / tabular figures.
   - A card holding a FactList uses `Card className="flex flex-col gap-3"`.
   - Update the unit tests of these four screens if they assert the old grid classes. Never weaken what they check.
4. **Delete `src/app/(owner)/fatture/detail.tsx`.** Its last importers are gone; grep `src/`, `tests/` and `e2e/` for `Detail`,
   `DETAIL_LIST_CLASS` and `fatture/detail`. No alias.
5. **`menu-item-form.tsx` `font-display`.** Use `Heading` or `SubHeading` (whichever matches the existing size or level) instead of the
   hand-set display font.
6. **e2e `gestione-theme.spec.ts`.** Follow `e2e/chiusura-theme.spec.ts`:
   - one page per root that an owner can open with fake data, read empty: light and dark body, Forest band, Montserrat h1;
   - the primary is readable where the page really has one;
   - the `locator`s must exist on that page, and a selected segment is not a primary;
   - wait for the scheme's body background before reading contrast.
   - Pages that need a factor or a device (doppia-verifica, password, sicurezza, dispositivi) may be left out if an owner can't reach
     them with the e2e helpers; say which and why in the spec header.
   - Run `env -u CI npx playwright test --list --forbid-only`.

## Not in scope
- Changing any finished slice's look.
- The parked LedgerRow chevron and the invoice-list or quality-summary moves.
- Step 8 (guest `/prenota`).

## Risks
- The `FactRow` migration could change how a missing value shows. Keep `Detail`'s "left out" rule, and test that a null row is absent.
- The e2e pages may need data. Read them empty, as P2g did.
