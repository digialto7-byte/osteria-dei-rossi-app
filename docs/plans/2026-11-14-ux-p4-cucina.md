## 0. Summary

Twelve commits. **No server change is needed**: every number and list P4 shows is already in an API the chef may read (§2.4).
- **K1** reads the open comande and "Da fare" from `GET /api/kitchen/tickets`, the same reply `/cucina` shows, on Home. It reads once,
  then again only when the page comes back to the front. No timer.
- **K-d** removes the chef's plain "Comande" row from Home once the card is there.
- **K2** takes the chef's recent batch recipes from `GET /api/batches` (newest first, `byMe`), read once with the recipe list.
- **K3** is a new page `/magazzino/spreco` that reuses `GET /api/stock`, `GET /api/stock/lots`, the existing `WasteForm` and
  `POST /api/stock/waste`, all unchanged. Home's "Registra uno spreco" moves there, and QW9's `?azione=spreco` list mode is removed
  (no shim, rule B).

One gate: a new page under `(owner)` turns `tests/config/m25b-preserves.test.ts:207-212` red until `"magazzino/spreco/page.tsx"` is
on its allow-list (`:89-100`). That file is outside this builder's paths (P4-BQ-1). So the K3 steps come last, and variant V1 splits
them off if P4-BQ-1 is not cleared.

No migration, no new dependency, no new poll, no new secret, no new money figure.

### 2.2 `/cucina` and its API (read only for this builder)

- **`GET /api/kitchen/tickets`** (`src/app/api/kitchen/tickets/route.ts:5-7`)
  - Roles: chef, owner and admin. The waiter gets 403 before any RPC. It sends `cache-control: no-store`.
- **`kitchenTicketsOutput`** (`src/server/kitchen/output.ts:44-51`)
  - It is strict, has no euro key, and its keys pass pgTAP 059's chef regex (`:4-6`).
  - `tickets` holds the **active** comande. `closedTickets` holds the closed ones.
  - `remaining` is "the dishes still to make on the active comande, counted in SQL", across **all** active comande before the cap
    (`supabase/migrations/20261111100200_kitchen_board.sql:9-10`; current body `20261130100400_weight_reads.sql:174-180`).
  - `truncated` is true when **either** list was cut at 200 (`KITCHEN_MAX_TICKETS`, `src/server/kitchen/constants.ts:6`).
- **`/cucina` polls** every `KITCHEN_POLL_MS` (5 s, `constants.ts:2`) and on `visibilitychange` and `focus`, and skips while
  `document.hidden` (`cucina/page.tsx:109-127`, guard at `:114`). P4 does not touch this poll.
- **Fixture:** `tests/helpers/kitchen-data.ts` `KITCHEN_TICKETS` has 2 active tickets, `remaining: 2`, `truncated: false` (`:19-22`).
  Read only here; tests may import it.

**K1 needs no server change.** The count of active comande is `tickets.length`. It is exact unless
`truncated && tickets.length === KITCHEN_MAX_TICKETS`, which the card words as "200 o più" (D2). "Da fare" is `remaining`.

**The APIs (read only)**
- **`GET /api/recipes`** (`src/server/recipes/list.ts:49-84`)
  - Returns `key`, `name`, `type`, `version`, `validFrom`, `isActive` and `allergens`, sorted by name.
  - **No last-production field.**
- **`GET /api/batches`** (`src/app/api/batches/route.ts:10-20`)
  - Roles: chef, owner and admin.
  - Returns the newest 50 batches first (`BATCH_LIST_PAGE_SIZE`, `src/server/batches/constants.ts:10`; SQL order
    `20261028100400_batch_reads.sql:36-57`).
  - Each item has `recipeKey`, `recipeName`, `producedAt` and `byMe` (`src/server/batches/output.ts:88-108`).
  - The chef's reply has no cost key: `listBatches(…, withCosts=false)` parses `batchListResponse` (`src/server/batches/list.ts:50`).
  - A split batch copies its parent's `produced_at` and `produced_by` (`20261029100300_batch_split.sql:89-92`), so deduping by recipe
    absorbs splits.

**K2 needs no server change.** The "recent list" is the distinct `recipeKey`s of the first page of `/api/batches` with `byMe`, kept
only when the recipe is in the active batch list.

**Founder standing rules**
- **Rule A.** No new polling.
  - K1: one read on mount, then one per return to the front (D3); none while hidden; no interval.
  - K2: one read of `/api/batches`, with the recipes, on mount.
  - K3: `/api/stock` on mount; `/api/stock/lots` when an ingredient is chosen; both once after each saved waste.
  - `/cucina`'s 5 s poll is unchanged.
- **Rule B.** No silent catch, and no fallback except as a product requirement or a reported failure.
  - K1: the failure is said in the card, and no number is invented while loading (D2).
  - K2: the failure is said, and the select stays (D7).
  - K3: a failed read or write shows `ErrorAlert` with the API's message (as the ingredient page does), and a 403 shows
    `stock.forbidden`.
  - No shim: QW9's list mode is removed (D13).
- **Chef never sees money.** `/api/kitchen/tickets` and the chef's `/api/batches` carry no euro key (strict schemas, §2.2, §2.3).
  `/api/stock` is quantities only. Every new screen state is checked for "€" (§5).

### 4.4 Sequences

**K1 (chef on Home)**
1. `GET /api/me` (cached).
2. In parallel: `GET /api/today`, `GET /api/alerts?filter=open&limit=3` and `GET /api/kitchen/tickets`.
3. The card shows `kitchenCardText(kitchenHomeCard(reply))`.
4. On `visibilitychange` with the page visible: `GET /api/kitchen/tickets` once more.

**K2**
1. `GET /api/recipes?type=batch` and `GET /api/batches` in parallel.
2. `recentRecipes(batches.items, recipes)`.
3. The form renders.
4. A tap on a recent button sets `recipeKey` and focuses `output`.
5. Then as today: "Calcola" calls `GET /api/batches/proposal`, and "Registra" calls `POST /api/batches`.

**K3**
1. `GET /api/stock`.
2. The chef types; `filterByName(items, query)` narrows the list.
3. A tap on a result calls `GET /api/stock/lots?ingredient=<id>`, and `WasteForm` mounts with `autoFocusQty`.
4. "Registra spreco" calls `POST /api/stock/waste` with `{ ingredientId, qty, unit, reason, locationId?, lotId? }` (`wasteBody`,
   unchanged).
5. On 201: the status note, the negative note when `negative`, then `GET /api/stock` and `GET /api/stock/lots?ingredient=` once.

### 4.5 Data and API

- No data model, endpoint or response change.
- No personal data beyond what the chef already reads on `/cucina`: the kitchen reply carries table names and the firing waiter's
  display name. Home shows **counts only** and keeps nothing.
- No `localStorage` or `sessionStorage` use is added.
